## Global Constraints

- Native Android only, Tools/home only, after the whole Recent files list/empty state and before All tools; suppress search/incoming selection/all other routes. No bottom or Recents fallback.
- Protocol 1; **maximum height 100 dp**; measure actual loaded height before display. Full creative must fit; do not stretch/crop it.
- Existing versions and IDs only; package `com.reampdf.mobile`, min SDK 24, compile/target 36, Java 21. No `node_modules`, generated Gradle, signing/private-key/OTA authority changes or SDK upgrades.
- Keep UMP `canRequestAds`, under-age-of-consent `true`, General rating; do not introduce COPPA assumptions. Native validates current configuration, not arbitrary JS IDs.
- Zero ad requests from scroll/resize observation alone; no-fill backoff **60 seconds** on later eligible entry; persistent protocol failure collapses after **1 second**. **50 ms** stale-scroll budget is a conservative suppression input, never proof of safety.
- One ad owner; measured two-phase slot acknowledgment; generation/sequence guards; no-fullscreen touch layer; reject unsupported scale/geometry and fail closed.
- Default browser/website: no fake creative/no blank gap. Optional placeholder only with `import.meta.env.DEV && VITE_REAM_INLINE_AD_PREVIEW === 'true'` and explicit development label.
- Local proof/build/integration may proceed without hardware after plan approval and primary review of the first proof task. Native production host remains disabled pending device gate. No production ad clicks, APK installation, signing, OTA publication or store submission in this local-build scope.
- New native bridge requires a new APK/AAB; older installed bridge/unknown capability yields no banner safely. Preserve live previews on 5173/5174 and other agents' website policies/icons work.
- No Git delivery steps in this plan. Only explicitly authorized reviewed scoped commits/pushes may be added later; never stage unrelated policy/assets/spec work.

## Review Focus

1. Late callback or geometry packet from a retired route must not resurrect an ad; Task 1 native session tests and Task 3 controller tests pin this.
2. Display-size/font changes, native origins and IME insets must not move a touch target over recent/tool controls; Task 1 mapping tests and Task 4 DOM tests pin local behavior, Task 6 devices pin actual compositing.

5. No-fill/offscreen/strict-mode remount/slow bridge must not cause a reload loop or blank permanent gap; Tasks 3–4 tests pin request counts, height and cleanup.

### Contract decisions used by all tasks

`inlineBanner.ts` exports `TOOLS_BANNER_PROTOCOL = 1`, `RectCss = {x:number,y:number,width:number,height:number}` and these types:

- `Capabilities = {protocol:1,supported:boolean,mode:'android-debug'|'production'|'disabled',canRequest:boolean,reason?:string}`. `canRequest` describes native eligibility, not a consent grant from JS.
- `Geometry = {generation:number,sequence:number,slot:RectCss,creative:RectCss,scrollX:number,scrollY:number,layoutWidth:number,layoutHeight:number,visual:{offsetLeft:number,offsetTop:number,width:number,height:number,scale:number},occlusions:RectCss[],reservedHeight:number,eligible:boolean}`. Coordinates are CSS viewport pixels; native capture supplies its own density/origins/scroll/monotonic receipt time.
- `PrepareOptions = {generation:number,widthCss:number,layoutWidth:number,eligible:boolean}`; no JS adId, consent grant or production-enable option.
- `BannerState = {generation:number,sequence?:number,status:'loading'|'measured'|'visible'|'hidden'|'failed'|'destroyed',widthPx:number,heightPx:number,heightCss:number,reason?:string}`.
- `ToolsBannerPlugin`: `getCapabilities():Promise<Capabilities>`, `prepare(options:PrepareOptions):Promise<void>`, `updateGeometry(geometry:Geometry):Promise<{accepted:boolean,sequence:number}>`, `hide({generation}:{generation:number}):Promise<void>`, `destroy({generation}:{generation:number}):Promise<void>`, `addListener('stateChanged',listener:(event:BannerState)=>void):Promise<PluginListenerHandle>`.

Use `registerPlugin<ToolsBannerPlugin>('ToolsBanner')`. Local Android methods use identical names/fields; parse missing/invalid values fail closed. `hide/destroy` must not be blocked by invalid geometry or denied consent. No JS API can force production capability.

Pure controller contract in `inlineBannerController.ts`: `createInlineBannerController(bridge:ToolsBannerPlugin,clock:()=>number,onState:(state:BannerState)=>void):InlineBannerController`; controller methods `enter(options:PrepareOptions):Promise<void>`, `update(geometry:Geometry):Promise<void>`, `leave():Promise<void>`, `dispose():Promise<void>`. Fake bridge implements the same interface in tests; no production `window` mock hook.

Component contract in `ToolsBannerSlot.tsx`: export `InlineBannerControllerFactory = (onState:(state:BannerState)=>void)=>InlineBannerController`, `ToolsBannerSlotViewProps = {eligible:boolean,createController:InlineBannerControllerFactory}`, and `ToolsBannerSlotView(props:ToolsBannerSlotViewProps):React.JSX.Element|null`. This view owns the actual slot/label DOM, measurement/observers and height/ack behavior. The product wrapper remains `ToolsBannerSlot({eligible}:{eligible:boolean}):React.JSX.Element|null`: native platform/initialization gating is here, and its factory always calls the real `createInlineBannerController` with the `registerPlugin` native adapter. It accepts no bridge/factory/testing prop and has no runtime/global/query bypass. Injection is ordinary typed React composition into the shared view, not a consent grant, native ID selector or production-enablement mechanism; the native host still enforces all authority/configuration checks.

The isolated fixture imports **that same `ToolsBannerSlotView`** and the real `createInlineBannerController`; its factory passes a fixture-local fake `ToolsBannerPlugin` and controlled clock. `tools-banner-slot.tsx` exports `mountFixture(options:{eligible:boolean,strictMode:boolean}):void`, `setEligible(eligible:boolean):void`, `emitMeasured(heightCss:number):void`, `emitFailure(reason:string):void`, `setAckEnabled(enabled:boolean):void`, `readTrace():{prepareCalls:number,geometry:Geometry[],destroyCalls:number,listeners:number}`, and `unmountFixture():void`. Playwright obtains these via dynamic import of the fixture module in page.evaluate, not window globals. Fixture fake events retain the current generation; stale-event tests use a dedicated retired fixture generation. Assertions inspect the actual rendered DOM and trace. Product Home insertion/order/default-browser checks run separately against the actual app; they do not pretend fixture scaffolding is Home integration.

Pure native contracts use Java immutable classes, not Android UI/JSON dependencies in unit tests: `ToolsBannerGeometry.map(Snapshot,NativeViewport):Decision`; `Decision` has `valid`, `visible`, `framePx`, `heightCss`, `reason`; `ToolsBannerSession.begin(long generation,int widthDp,long nowMs):boolean`, `accept(long generation,long sequence):boolean`, `retire(long generation):void`, `mayRetry(long nowMs):boolean`; `ToolsBannerAuthority.validate(Metadata active,Metadata installed,boolean debuggable,boolean productionVerified):Result`; `ToolsBannerGesture.update(Action action,float x,float y,int pointers):Ownership` with `Ownership` AD, WEBVIEW, CANCELLED. Constructors and immutable inputs are defined in the first task's test fixtures; later code must use them rather than duplicate decisions.
